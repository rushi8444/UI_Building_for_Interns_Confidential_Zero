190: ## Implementation notes
191: 
192: Points worth knowing before modifying this:
193: 
194: - **Prices use a 1e9 divider.** `Price` derives from `UnsignedMonetary<...,9>`,
195:   so `Price::divider` is 1,000,000,000. Use `Price::toDouble()`. Treating the
196:   fraction as 1e4 yields values 100,000x too large.
197: - **Compact prices are packed**, not plain integers. `GetLastPrice()` and
198:   `GetLastOrClosePrice()` return compact form and must go through
199:   `Price::SetCompactValue()`.
200: - **Extension observers receive `TM_*` messages, not `M_*`.** The `M_BOOK_*`
201:   constants are raw feed protocol types and are never delivered to extensions.
202:   Level 1 updates arrive as `TM_STOCK_UPDATE_LEVEL1` (64020).
203: - **Book reads require the Level 2 lock** (`LockInquiryWaitLevel2` /
204:   `UnlockInquiryLevel2`) when performed off the security's worker thread.
205: - **`TD_ObtainStock(symbol, true)` subscribes; `TD_FindStock` does not.** Use
206:   Obtain, and balance it with `TD_ReleaseStock`.
207: - **Securities are not in storage until login completes.** The subscription
208:   thread retries every 2s rather than attempting once at startup.
209: - **MMIDs are mixed case** (`nsdq` and `IEX` both occur). Do not use case as a
210:   validity test if you add depth handling later.

# How This Works — From Zero (A Guide Even a Beginner Can Follow)

This explains the whole project from scratch: what it does, why, and how to
rebuild it yourself. No prior knowledge assumed.

---

## Part 1 — What are we even doing?

Takion is a stock-trading program. On its screen it shows a **"Level 2" box** (a
"montage") — a live list of who wants to buy and sell a stock, at what price, and
how many shares. Example:

```
BID (buyers)            ASK (sellers)
1300  NSDQ  708.29      924  NSDQ  708.30
1020  ARCA  708.29       80  MEMX  708.32
 700  EDGX  708.29       50  NSDQ  708.35
```

We want to **grab that list, continuously, and save it to a file** so we can
study it later or feed it to a trading model. Takion won't just hand it to us
through a normal "export" button, so we build a tool that reaches inside Takion
and copies it out.

**Analogy:** Takion is a chef cooking a dish (the data). We're not allowed to ask
the chef for the recipe. But we're allowed to stand *inside the kitchen* (Takion
lets us load our own code), so we peek at the ingredients on the counter and
write them down ourselves.

---

## Part 2 — The three pieces

```
[ Takion program ] --> [ Our DLL inside it ] --> [ pipe ] --> [ Python ] --> [ file ]
   has the data        copies the data out      a tube      catches it     saves it
```

1. **The DLL** — a small program (`TakionAdditionalColumns.dll`) that Takion
   *loads into itself*. Because it runs *inside* Takion, it can see Takion's data.
2. **The pipe** — a "named pipe" is like a garden hose between two programs on the
   same computer. The DLL pours data in one end.
3. **The Python script** — sits at the other end of the hose, catches the data,
   and writes it into `.parquet` files (a compact spreadsheet format).

**Words you'll see:**
- **DLL** = a program that plugs into another program (instead of running alone).
- **Named pipe** = a private tube for two programs to pass data fast.
- **Order book / Level 2 / "depth"** = the full list of buy and sell offers.
- **MMID / venue** = which exchange the offer is on (NSDQ = Nasdaq, ARCA, etc.).
- **Bid** = a buy offer. **Ask** = a sell offer.

---

## Part 3 — What you need installed

1. **Visual Studio Build Tools** with the "Desktop development with C++" workload
   **and MFC** (a checkbox in the installer). This compiles the DLL.
2. **The Takion SDK** — the header files (`.h`) and library files (`.lib`) that
   let our code talk to Takion. (In this package: `sdk\` and `lib\`.)
3. **The VC++ runtime** — `prereq\vc_redist.x64_14.51.exe`. Install it first, or
   the DLL won't load (error `0xc000007b`). It must be version 14.51 or newer.
4. **Python 3.10–3.13**, then in a terminal: `pip install pywin32 pandas pyarrow`.
5. **An entitled Takion account** — one that's allowed to see Level 2 data. If
   the account isn't allowed, there's nothing to copy.

---

## Part 4 — Build the DLL (turn code into the plug-in)

1. Put the Takion `.lib` files in the `lib\` folder (Observer.lib, TakionData.lib,
   TakionGui.lib, TakionLog.lib, TakionMemory.lib, TakionUtils.lib, Utils.lib).
2. Double-click `build.bat` (or run it in a terminal). It:
   - Loads the compiler.
   - Compiles the `.cpp` files in `src\`.
   - Links them with the `.lib` files.
   - Produces `bin\TakionAdditionalColumns.dll`.
3. Success looks like `=== BUILD SUCCESSFUL ===`.

**Common error:** `C1189: include 'stdafx.h' before including this file`. This
means the very first `#include` in `ColumnFunctions.cpp` is NOT `stdafx.h`. Fix:
make sure `#include "stdafx.h"` is the first line of includes. (An auto-formatter
loves to move it — a `// clang-format off` comment above it stops that.)

---

## Part 5 — Install the DLL into Takion

1. Close Takion (Windows locks a DLL while it's in use).
2. Copy `bin\TakionAdditionalColumns.dll` into `C:\Takion\` (or run `deploy.bat`).
3. Tell Takion to load it — in `C:\Takion\takion.ini`:
   ```

   ```

## Part 6 — Run everything (order matters!)

1. **Start the Python catcher FIRST:** `py python\omnitrix_depth.py`
   (It creates the pipe and waits. It's the "server". If you start it second,

2. **Start Takion, log in.**
3. **Open the Level 2 montage windows** for the stocks you want (NVDA, QQQ, AAPL).

   `data\<date>\nvda_depth.parquet`. Done.

## Part 7 — HOW THE MAGIC ACTUALLY WORKS (the important part)

### Why we can't just ask nicely

Takion has official functions (an "API") to read the book. We tried **all of
them** — `GetBook`, iterators, `Level2Calculator`, message observers. Every one
returned only a few small "regional" exchanges (MEMX, MIAX, PHLX…) and **never**
the big ones (NSDQ, ARCA, BATS…). The full data is kept in the montage *window's*
private memory, which the API doesn't share. So we read it out of memory
ourselves.

### The idea of a "pointer" and an "offset"

Think of the computer's memory as a giant street of houses, each with an address.
- A **pointer** is a piece of paper with a house address written on it.
- An **offset** is "go to that house, then walk N steps down the street."

Takion keeps a **Security object** for each stock (like a folder holding
everything about NVDA). We get its address from Takion. Then:

> At the Security's address **+ 0x1188** (that's an offset, 4488 steps), there is
> a **pointer** — a paper telling us the address of the actual order-book list.

We follow that pointer, and we're standing right in front of the list.

### What the list looks like (the "struct")

The list is many small blocks, **24 bytes each**. One block = one order-book row.
Reading around each 4-letter venue name (like "NSDQ"), the block is:

```
step -12:  price dollars     e.g. 708
step  -8:  price fraction    e.g. 290000000  ->  divide by 1,000,000,000 = 0.29
step  -4:  size in shares    e.g. 1300
step   0:  venue name        e.g. "NSDQ"
step  +4:  a timestamp        (we ignore it)
step  +8:  book id            (which exchange, as a number)
```

So the real price = **708 + 0.29 = $708.29**. The size is **1300 shares**. The
venue is **NSDQ**. That's one row of the montage — exactly what's on screen.

### Making sure we never save garbage

Reading raw memory is risky — if we read the wrong spot we'd get nonsense
numbers. So we use a **safety check**:
- Takion has ONE function that still works: it tells us the *best* bid and ask
  price (the "NBBO"). We trust that.
- For every row we pull from memory, we check: **is this price within a few
  dollars of the best price?** If yes, keep it. If it's wildly off (like $9,000
  for a $708 stock), **throw it away.**

This means if our memory-reading is ever wrong, we get **nothing** instead of
**wrong data**. For trading, wrong data is far more dangerous than no data.

### Not crashing Takion

Reading a bad memory address normally crashes the whole program. We wrap every
read in a **"try/except" safety net** (called SEH) so if a read fails, our tool
quietly shrugs instead of crashing Takion.

---

## Part 8 — How to FIND the `0x1188` number yourself (advanced, but explained)

The `0x1188` offset is like a secret map coordinate. It's specific to *this*
version of Takion. If Takion updates, the coordinate moves and you must find the
new one. Here's how it was found, using a debugger called **WinDbg**:

1. Open WinDbg and attach it to `Takion.exe` (with Takion running).
2. Search all of memory for the text "QQQ":
   ```
   s -a 0x0 L?0x7FFFFFFFFFFF "QQQ"
   ```
3. Takion keeps a phone book: the stock name "QQQ" is written down, and right
   after it is the **address of QQQ's Security object**. You just found the
   Security's address.
4. From there, we followed each pointer inside the Security and checked which one
   led to a list of prices matching the live best-price. The winner was the
   pointer at **+0x1188**.

**When depth stops working** (Python shows `extracted=0` forever) after a Takion
update, that coordinate moved — repeat these steps to find the new offset, then
change `0x1188` in the code.

---

## Part 9 — The data format (for the Python side)

Each row the pipe sends is exactly **32 bytes**, packed like this:

| bytes | field  | meaning                     |
|-------|--------|-----------------------------|
| 0–7   | symbol | stock, e.g. "NVDA"          |
| 8–15  | mmid   | venue, e.g. "NSDQ"          |
| 16–23 | price  | a decimal number (double)   |
| 24–27 | size   | shares (whole number)       |
| 28    | side   | 'B' = bid, 'A' = ask        |
| 29–31 | pad    | filler for alignment        |

In Python you unpack it with the format string `'<8s8sdIc3x'`. The consumer reads
32 bytes at a time and turns each into one row.

---

## Part 10 — When something's wrong (troubleshooting)

| You see… | It means… |
|---|---|
| No `fable_debug.log` file | Takion didn't load the DLL. Check `takion.ini` and that the DLL is in `C:\Takion`. |
| `waiting: 3/3 symbols not found` | You're not logged in yet, or the stocks aren't loaded. It keeps retrying. |
| `extracted=0` forever | The montage window isn't open, OR Takion updated and the `0x1188` offset moved (see Part 8). |
| Python prints nothing | Python wasn't started first, or the record size isn't 32 (a code/format mismatch). |
| `dropped=` going up | Python can't keep up; the fast buffer is overflowing (usually fine for logging). |

---

## Part 11 — The golden rules to remember

1. **Start Python before Takion.** (Server before client.)
2. **Open the montage windows.** (No window = no data in memory.)
3. **`0x1188` is temporary.** It breaks on Takion updates — re-find it with WinDbg.
4. **The NBBO safety check** means it fails *empty*, never *wrong*.
5. **It only reads, never writes.** It copies data out; it never changes Takion or
   sends anything over the internet — just the local pipe.

That's the whole thing. Install the tools, build the DLL, drop it in Takion, run
Python, open the montages — and the full order book streams into your files.

That's a complete from-scratch guide — concepts, build, run, the memory trick, the WinDbg hunt, the format, troubleshooting, all in plain language.

40: 
41: The full ladder is read directly from the Takion process heap: a 64-bit pointer at

44: extracted price is validated against the live NBBO (from CalculateL2BidPriceAndSize)

187: ## Implementation notes
188: 
189: Points worth knowing before modifying this:
190: 
191: - **Prices use a 1e9 divider.** `Price` derives from `UnsignedMonetary<...,9>`,
192:   so `Price::divider` is 1,000,000,000. Use `Price::toDouble()`. Treating the
193:   fraction as 1e4 yields values 100,000x too large.
194: - **Compact prices are packed**, not plain integers. `GetLastPrice()` and
195:   `GetLastOrClosePrice()` return compact form and must go through
196:   `Price::SetCompactValue()`.
197: - **Extension observers receive `TM_*` messages, not `M_*`.** The `M_BOOK_*`
198:   constants are raw feed protocol types and are never delivered to extensions.
199:   Level 1 updates arrive as `TM_STOCK_UPDATE_LEVEL1` (64020).
200: - **`TD_ObtainStock(symbol, true)` subscribes; `TD_FindStock` does not.** Use
201:   Obtain, and balance it with `TD_ReleaseStock`.
202: - **Securities are not in storage until login completes.** The subscription
203:   thread retries every 2s rather than attempting once at startup.
204: - **MMIDs are mixed case** (`nsdq` and `IEX` both occur). Do not use case as a
205:   validity test if you add depth handling later.
